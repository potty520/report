### 服务

```bash
systemctl status report-api          # 应用（JVM 限 256m：-Xms96m -Xmx256m -XX:MaxMetaspaceSize=192m -XX:+UseSerialGC）
systemctl restart report-api         # 重启
systemctl reload nginx               # 改 nginx 后重载（先 nginx -t）
journalctl -u report-api -n 100      # systemd 日志
tail -f /opt/report/logs/report-api.log
```

> 服务器内存紧张（2 GB，另有考勤/清账两套系统各占 200 MB 以上），**不要并行跑多个 Maven 构建**；
> 历史上出现过 mysqld 被 OOM 杀掉的情况。构建时建议 `MAVEN_OPTS='-Xmx384m -XX:MaxMetaspaceSize=192m'`。

## 2. 部署流程（标准动作）

```bash
# 0) 备份（每次部署前必做）
ts=$(date +%Y%m%d-%H%M%S); mkdir -p /root/backup-$ts
cp -a /opt/report/jar/report-system-1.0.0.jar /opt/report/application-prod.yml \
      /etc/nginx/conf.d/report.conf /root/backup-$ts/
cp -a /opt/report/web /root/backup-$ts/web

# 1) 数据库迁移（只做加法、幂等，可重复执行；顺序不能反——先建表/菜单，再上新代码）
mysql -uroot report_system < docs/report_2.0_upgrade5_backend.sql        # 6 张新表
mysql -uroot report_system < docs/report_2.0_upgrade4_audit_menus.sql    # 菜单 83–94 + 角色授权

# 2) 后端打包（服务仍在运行，不动 jar）
cd backend && MAVEN_OPTS='-Xmx384m' mvn -B clean package -DskipTests

# 3) 换 jar + 换前端（原子窗口：停 → 换 → 起）
systemctl stop report-api
cp -f backend/target/report-system-1.0.0.jar /opt/report/jar/report-system-1.0.0.jar
rm -rf /opt/report/web/* && tar -xzf dist.tar.gz -C /opt/report/web
systemctl start report-api
sleep 25 && curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8091/api/auth/captcha   # 期望 200
```

## 3. 关键配置（`application-prod.yml`）

```yaml
server:
  port: 8763
  servlet:
    context-path: /api
spring:
  servlet:
    multipart:
      max-file-size: 50MB          # 单文件
      max-request-size: 60MB       # 单请求（与 nginx client_max_body_size 保持一致）
  file:
    root: /opt/report/files
    max-size-mb: 200
  schedule:
    periodic-task-cron: "0 5 0 * * ?"    # 每天 00:05 生成周期子任务
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/report_system?...
```

可选开关（默认关闭，需要外部服务/凭据）：

| 配置/环境变量 | 默认 | 说明 |
|---|---|---|
| `report.sms.enabled` / `REPORT_SMS_ENABLED` | `false` | 短信催办开关；`provider=log` 只写日志 |
| `report.sms.provider` | `log` | 值 `chunlan` 走创蓝网关（需 `accessKeyId`/`accessKeySecret`） |
| `report.quality.provider` | `none` | 值 `http` 走外部质检服务（需 `report.quality.url`） |
| `report.quality.required` | `false` | 置 `true` 则"报告未生成不可审核"硬拦截 |
| `report.captcha.fixed-code` | `8888` | **自动化测试后门，上线前必须删除** |

## 4. 已知部署坑（都踩过，务必按此配置）

1. **nginx 分块编码**：`/api/` 必须用 `proxy_http_version 1.0` + `proxy_buffering on` +
   `chunked_transfer_encoding off`。改成 `1.1` 会让浏览器出现更多
   `ERR_INVALID_CHUNKED_ENCODING`（原因：上游 keep-alive 复用与 Tomcat 关闭空闲连接撞车）。
   详见 `docs/deploy/nginx-report.conf` 文件头。
2. **上传上限要改两处**：nginx `client_max_body_size` **和** Spring `spring.servlet.multipart`
   （默认都是 1MB，只改一处仍然 413）。
3. **菜单迁移必须显式给 `menu_code`**：`sys_menu.menu_code` 有唯一键且默认 `''`，
   不给值会从第二条起被 `INSERT IGNORE` 静默跳过（表现为"脚本成功但只进去一条菜单"）。
4. **菜单 id 用 83–94**：线上 `sys_menu` 的 id 空间与 `DataInitializer` 的种子 id 不同
   （线上 7=填报管理、22=角色管理；种子里 22=填报审核），套用种子 id 会把菜单挂错父级。
5. **`--spring.config.location` 指定的 `application-prod.yml` 是唯一生效配置**，
   改 `jar` 内或源码里的 `application.yml` 对线上无效（`DataInitializer` 也是 `//@Component` 未启用）。
6. **前端换版后浏览器要强刷**：`index.html` 变了，旧缓存的 hash 资源会 404。

## 6. 前端技术栈与构建

- React 18 + TypeScript + Vite 5 + antd 5 + zustand + react-router 6 + echarts
- 菜单**后端下发**（`sys_menu` → `GET /auth/menu`）；前端路由在 `src/App.tsx`
- 构建：`cd frontend2 && npm run build`（产出 `dist/`；`tsc -b` 与 vite build 必须都通过）

### 前后端契约注意

`rpt_template` 的后端字段是 `templateName/templateCode/fillingCycle/materialized`，
`rpt_template_field` 是 `fieldName(中文名)/fieldCode/dbColumn/isRequired`；
早期页面用的是 `name/code/version` 与 `fieldLabel/required`。
**归一化统一放在 `src/services/api.ts` 模板段**（读写双向转换），页面不要再各自假设字段名。
