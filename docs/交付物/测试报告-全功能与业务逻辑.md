### 问题 1：补正后无法重新填报（已修复）

- 现象：管理员对已审核数据发起补正后，填报人打开表单提交，被提示
  **「该数据已审核通过，不能再修改；如需修改请由管理员发起补正」**。
- 根因：`RptTaskDataService.startCorrect()` 只把 `status` 改回 0，没清 `audit_status / dept_audit_status / task_audit_status`；
  `fillData()` 里「已审核通过不许修改」的守卫因此仍然生效，补正流程直接走死。
- 修复：补正时一并清空上一轮审核状态、审核人、审核时间与意见（用 `lambdaUpdate` 显式置 NULL，
  因为 `updateById` 默认忽略 null 字段）。
- 复验：补正 → 填报人打开表单 → 修改 → 提交成功（截图 `69-fill-resubmit.png`）。

### 问题 2：首次填报无入口（已修复）

- 现象：任务分派给「总公司」后，填报人 `user` 登录，「我的填报任务」列表为空，无从下手。
- 根因：页面调用 `/fill/task/page`（查 `rpt_task_data`），只有存过草稿或提交过的任务才出现；
  后端其实早已提供 `/fill/my-assigned`（含未填报任务），但前端没接。
- 修复：`Fill/Task` 同时拉取「已分派任务」，与已有记录合并展示，未填报行标记「未填报」；
  首次打开时后端返回「未找到填报数据」不再当成失败，按空表单继续。
- 复验：新任务出现在列表并可填报（截图 `24-fill-list.png`）。

### 问题 3：多角色菜单重复（已修复）

- 现象：`user` 有「部门管理员 + 填报员」两个角色，左侧菜单里「填报总览」「消息中心」各出现两次（见 `32-todo-user.png`）。
- 根因：`SysMenuMapper.selectMenusByUserId` 的 SQL 按角色 join 且没有 `DISTINCT`，一个菜单被 N 个角色命中就返回 N 条。
- 修复：SQL 改为 `SELECT DISTINCT m.*`。
- 复验：重新登录后菜单不再重复（`66-login-user.png`）。

### 问题 4：数据申请无法提交（已修复）

- 现象：表单三项（标题/原因/数据范围）都填好后点确定，返回 **「系统异常，请联系管理员」**，列表无数据（`31-apply-result.png`）。
- 根因：前端提交 `{title, reason, dataScope}` JSON；后端 `DataApplyController.apply` 要求 `@RequestParam Long taskId` +
  `reason`，缺必填参数抛 `MissingServletRequestParameterException`，被兜底成「系统异常」。
  且 `title / dataScope` 在 `rpt_data_apply` 表里没有对应字段（表里是 `task_id / reason / status`）。
- 建议：前端加「关联任务」选择并改为 query 参数提交；或后端改为接收 JSON 并放宽 `taskId`；
  两侧字段先对齐（title/dataScope 要么落库、要么从前端移除）。

### 问题 5：审核人无法通过界面分派（已修复）

- 现象：「任务分配」弹窗只有部门穿梭框，提交时固定 `assignType=FILL`（`Task/Assign/index.tsx:81-85`）。
- 影响：`/audit/myTasks`、`/audit/dept-audit` 等审核页依赖 AUDIT 分派，走界面建的任务没有审核人；
  本次测试是用接口补的 AUDIT 分派才跑通两级审核。
- 建议：分派弹窗增加「分派类型：填报/审核」选项（接口已支持 `assignType=AUDIT`），或分派时同时带出部门审核人。

### 问题 6：入库没有界面入口（已修复）

- 现象：全站检索不到「入库/写回」按钮，`POST /api/fill/{taskId}/commit` 只能手工调用。
- 影响：业务上「两级审核通过 → 写回业务库」这最后一步在界面上不可达，只能靠运维调接口。
- 建议：在审核详情页或任务台账加「入库」按钮（建议按任务/按数据两种粒度），并展示 `rows/affected/skipped` 结果。

## 四、结论与建议

1. **核心链路可用**：模板 → 任务 → 分派 → 填报 → 两级审核 → 入库 → 补正 → 重报 → 驳回，状态机与留痕均正确。
2. **界面完整度已补齐**：问题 4/5/6 都是「后端有能力、界面没入口」，本轮已接线并通过浏览器复验。
3. 六个问题均已修复并复验；后续新增业务页建议沿用「界面入口 + 接口幂等 + 轨迹留痕」三条验收标准。
4. 本次测试的 29 个页面截图与 71 个操作步骤已整理进《操作手册》（`操作手册.html`，截图内嵌，可直接分发）。
