## 1. 周期枚举统一（P0）

同一套枚举原来有 5 种写法，界面选「月度」后端按「日报」算，属期和截止日全错。

改动：
- `backend/.../service/PeriodService.java`
  - 常量固定为 1 日报 / 2 周报 / 3 月报 / 4 季报 / 5 年报 / **6 一次性**
  - 新增 `label()`、`validate()`、`isPeriodic()`
- `RptTemplateService.add/update`、`RptTaskService.createTask`：写库前 `PeriodService.validate(...)`，非法值直接报错而不是落库
- `RptTaskService.generatePeriodicTasks`：一次性（6）不再进 default 分支被当成月报，直接跳过
- `frontend2/.../Template/Wizard/index.tsx`：下拉改成 6 项，默认值改为「月报(3)」
- `frontend/.../Template/Add|List`（旧 Vue）：从字符串 `DAILY/MONTHLY` 改成数字 1–6，列表展示同步
- `docs/database.sql`、`docs/report_2.0_upgrade.sql`：注释与字典种子对齐，补 6=一次性
- 新增 `deploy/check_filling_cycle.sql`：**只读**核对脚本，列出分布、非法值、需要业务确认的模板

⚠️ 历史数据不做自动改写。旧界面存的 1/2/3/4 语义与新口径不同，必须用 `check_filling_cycle.sql` 逐条确认后再改（脚本里给了映射建议和示例 UPDATE）。

## 2. 时间整体慢 8 小时（P1）

JVM、JDBC、MySQL 三层时区不一致，所有时间列比真实北京时间早 8 小时，`CURDATE()` 还会让 0–8 点的提交算到前一天。

改动：
- `ReportApplication`：静态块 `TimeZone.setDefault(Asia/Shanghai)`，不依赖容器 TZ
- `application.yml`：Druid `connection-init-sqls: SET time_zone = '+08:00'`，数据库会话也固定东八区（不需要 MySQL 时区表）
- 新增 `deploy/fix_timezone_data.sql`：**只生成语句不执行**，用于把历史时间整体 +8 小时；脚本里写了备份、抽查、回滚步骤

上线后历史数据仍需跑一次；TIMESTAMP/DATETIME 都要 +8，脚本已覆盖。

## 3. 驳回不留痕 + 重报后残留驳回意见（P1）

- `RptTaskDataService.audit()`：补 `processLog.log(..., "AUDIT", "审核通过/审核驳回", "PASS/REJECT", ...)`，驳回终于进时间线
- `submitData()`：重新提交时清空 `audit_status/comment/user/time` 与两级审核字段，避免「已通过」却挂着上次驳回意见；轨迹上区分「提交填报 / 重新提交填报」
- `frontend2/.../Audit/Trajectory/index.tsx`：补 `AUDIT` 节点颜色

## 4. 待办数其实是未读消息数（P1）

原 `todoCount` = 未读站内消息，分派/催办每次都发消息且不去重，实测 52 个任务算出「待办 158」。

- `TodoService.summary()` 重写：
  - `todoCount` = 待填 + 待审 + 待批（真实待办）
  - 新增 `fillTodo / auditTodo / applyTodo / unreadCount / readCount`
  - `doneCount` 改为「我提交且通过 + 我审过」
  - 待审批只对有 `SUPER_ADMIN/DEPT_ADMIN/AUDIT_USER` 角色的人统计
- `notifyAssignees()`：同任务同类型只保留一条未读消息，消息不再无限堆积
- 前端：`api.ts` 类型补齐；顶栏红点改用 `unreadCount`；待办页 6 张卡（待办/待填/待审/已办/未读消息/超期）

## 5. 入库不幂等、不校验审核（P1）

- `RptTaskDataService.commitToTarget(taskId, dataId, operatorId, force)`：
  - 默认只允许两级审核通过的数据入库（兼容历史单级审核 `audit_status=1`）
  - 默认跳过 `inbound_status=1` 的数据；重复点「入库」不再插重复行
  - 返回值新增 `skippedInbound / skippedUnaudited`
- `FillController`：`/fill/{taskId}/commit` 增加可选 `force=false`；确需重灌传 `force=true`
- `application.yml`：`report.inbound.require-audit`（环境变量 `REPORT_INBOUND_REQUIRE_AUDIT`，默认 true，老部署可关）
- `MaterializeService.ensureTable`：模板没有主键字段时打 WARN，提示该表只能追加、无法 upsert

## 6. 顺带修掉的小问题

- 模板列表：`fillingCycle` 传字符串与 Integer 比较恒 false（一筛就空），且过滤在分页之后导致 total 不对。现在筛选与授权范围全部下推到 SQL，`total/pages` 正确；参数兼容 `1` 与 `DAILY/MONTHLY`
- 403 返回英文 `Access is denied` → 统一中文化（中文环境下 Spring Security 抛的是「不允许访问」，也一并归一成「无权限执行该操作」）
