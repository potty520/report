## 十二、Redis 预留与启用预案

当前版本**不依赖 Redis**，但依赖与配置骨架保留，后续启用不需要动架构。

### 现状（2026-10-24）

| 项 | 状态 |
|---|---|
| `spring-boot-starter-data-redis` / `commons-pool2` | 在 `pom.xml` 中，随包发布 |
| `RedisAutoConfiguration` | 在 `application.yml` 中被 `exclude` |
| `RedisConfig` | 整个类被注释（`@Configuration` / `@EnableCaching` 均未生效） |
| `SysMenuService` 上的 `@Cacheable` | 因未开缓存，实际不生效（每次查库，菜单表很小，无影响） |

### 启用步骤（单实例先行）

1. **配置**：`application.yml` 去掉 `spring.autoconfigure.exclude` 里的 Redis 项，加：

   ```yaml
   spring:
     data:
       redis:            # Boot 3 的键是 spring.data.redis（Boot 2 时代是 spring.redis）
         host: 127.0.0.1
         port: 6379
         password: ${REPORT_REDIS_PASSWORD:}
         database: 0
         timeout: 3s
   ```

2. **打开缓存**：`RedisConfig` 恢复 `@Configuration` + `@EnableCaching`，此时 `RedisCacheManager` 才会被创建，
   `SysMenuService` 的 `@Cacheable("menus")` 开始生效（修改菜单后需要 `@CacheEvict`，否则 30 分钟才过期）。

3. **三处内存态换成 Redis**（多实例必需，单实例可选）：

   | 组件 | 现状 | 改造要点 |
   |---|---|---|
   | `CaptchaStore` | `ConcurrentHashMap` | `SETEX captcha:{uuid} 120 {code}`，校验后 `DEL`（保持一次性语义） |
   | `LoginAttemptLimiter` | `ConcurrentHashMap` | `INCR login:fail:{user}:{ip}` + `EXPIRE`，锁定用 `SET lock:{user}:{ip} NX EX 300` |
   | `OnlineUserService` | 写 `rpt_online_user` 表 | 若要"强制下线"跨实例即时生效，会话状态放 Redis；否则保持数据库方案即可 |

4. **多实例还需要**（与 Redis 无关但必须一起做）：

   - 附件目录 `/opt/report/files` 改为共享存储（NFS 或对象存储），否则上传到 A 节点、B 节点下载不到；
   - 定时任务锁继续用现有的 `rpt_schedule_lock` 数据库锁即可，**不需要引入 Redisson**；
   - nginx 做上游负载均衡（`upstream` 里加两个 8763）。

### 政务外网注意事项

- Redis 必须设 `requirepass`，`bind` 只监听内网地址，禁止 0.0.0.0 暴露 6379；
- 禁用/重命名危险命令：`rename-command FLUSHALL ""`、`rename-command CONFIG ""`；
- 纳入等保测评范围（账号口令、访问控制、日志、补丁、备份）；
- 与 MySQL 一样，做好每日备份（RDB 快照 + AOF 视需要）。

> 目前不需要 Redis：单实例、JWT 无状态、定时任务已有数据库锁、数据量很小（用户 4 / 任务 16 / 填报 11 条）。
> 等出现"第二台应用节点"或查询压力上来时，按上面第 1–3 步启用即可。
